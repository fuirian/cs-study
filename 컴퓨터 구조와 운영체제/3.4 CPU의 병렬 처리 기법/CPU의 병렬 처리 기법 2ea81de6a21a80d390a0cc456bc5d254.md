# CPU의 병렬 처리 기법

- 현대 CPU는 성능 향상을 위해 명령어를 하나씩 직렬로 실행하는 대신 병렬 처리 기법 사용
- **병렬 처리**는 여러 명령어를 동시에 실행해 CPU의 처리 속도를 높이는 기법

### 파이프라이닝

- 가장 기본적인 병렬 처리 기법
- CPU가 명령어를 처리하는 과정을 여러 단계로 나누고, 각 단계를 병렬로 수행하는 방식
- 각 단계가 동시에 동작하기 때문에 명령어 처리 속도가 증가
- 파이프라이닝을 사용하면 CPU가 클럭 사이클마다 새로운 명령어 처리 가능
    1. 명령어 인출
    2. 명령어 해석
    3. 오퍼랜드 인출
    4. 실행
    5. 저장
- 직렬 처리 방식에서는 하나의 명령어를 처음부터 끝까지 실행한 후, 다음 명령어 실행

- 총 클럭 사이클 수는 `명령어 수 * 단계 수` 이므로 `25 클럭 사이클` 소요
- 각 명령어를 완진히 실행할 때까지 다음 명령어를 실행하지 못하므로 비효율적
- 파이프라이닝에서는 각 단계에서 서로 다른 명령어를 동시에 처리 가능
- 파이프라이닝 예시(명령어 5개 실행)

- CPU가 모든 단계를 동시에 수행할 수 있어 자원을 효율적으로 활용 가능

### 슈퍼스칼라

- CPU가 한 번에 여러 명령어를 병렬로 처리할 수 있도록 설계된 구조
- 일반적인 스칼라 CPU는 한 번에 하나의 명령어만 처리하지만, 슈퍼스칼라 CPU는 내부에 여러 **실행 유닛**을 배치해 여러 명령어를 동시에 실행 가능
- 슈퍼스칼라 CPU 실행 유닛
    - 산술 논리 연산 유닛
    - 부동 소수점 연산 유닛
    - 로드/스토어 유닛
- 슈퍼스칼라 구조에서는 기본 명령어 처리 과정에 명령어 발행 단계가 추가
- **명령어 발행**
    - 해석한 명령어를 적합한 실행 유닛으로 전달하는 단계
    - 명령어 간 데이터 의존성, 제어 의존성을 확인해 병렬로 실행 가능한 명령어를 식별
    - 명령어를 순차적으로 처리하지 않고, 병렬로 실행 가능한 명령어를 실행 유닛에 우선 배정
    - 병렬로 실행 가능한 명령어를 적절한 실행 유닛에 할당
- 명령어 발행 단계는 명령어 해석 단계에 통합해 처리하기도 하고, 독립 단계로 존재하기도 함
- 슈퍼스칼라는 다수의 실행 유닛을 사용하기 때문에 각 실행 유닛에 명령어를 적절히 분배하는 것이 중요
- 명령어 발행 단계가 얼마나 잘 설계되고 실행 유닛을 적절히 활용하는지에 따라 병렬 처리의 효율성이 달라짐
- 현대 CPU는 병렬 처리를 극대화하기 위해 이 단계를 독립적으로 구현하는 경우 다수

### 슈퍼 파이프라이닝

- 기존 파이프라이닝의 각 단계를 더 세분해 동시에 실행할 수 있는 명령어 수를 증가시키는 방법
- 일반 파이프라이닝은 보통 5~10단계로 구성
- 슈퍼 파이프라이닝은 15~20단계 이상으로 세분
- 최신 고성능 CPU에서는 30단계 이상 사용하기도 함
- 단계를 세분할수록 한 단계에서 처리해야 할 작업량이 줄어들어 단계별 작업 시간이 짧아지므로 CPU 클럭 속도를 더 높일 수 있음
- 클럭 속도 증가 → 전체 처리량 향상
- 단계가 많아질수록 명령어 간 데이터 의존성 문제를 해결해야 해서 부담 커짐
- 너무 많은 단계로 세분하면 제어 로직이 복잡해지고 오히려 성능 저하
- 고성능 데스크톱 CPU는 더 많은 단계로 세분한 슈퍼 파이프라이닝을 사용하지만, 저전력 모바일 CPU는 상대적으로 단순한 파이프라이닝을 유지해 전력 소비를 줄임

### VLIM

- 명령어 레벨 병렬성을 극대화하는 병렬 처리 방식
- 여러 개의 독립적인 명령어를 하나의 긴 명령어 워드에 포함해 동시에 실행
- 각 명령어는 여러 개의 실행 유닛에 할당되어 병렬로 처리
- 병렬 처리를 가능하게 하는 명령어 스케줄링은 컴파일러가 수행
- 슈퍼스칼라에서 사용하는 동적 스케줄링 대신 컴파일 단계에서 명령어를 병렬로 정리
- 컴파일러는 명령어 간 데이터 의존성을 분석해 병렬로 실행 가능한 명령어를 한 명령어 워드로 묶음
- 하드웨어는 명령어 워드를 그대로 실행만 하므로 스케줄링 불필요
- 한 클럭 사이클에서 여러 명령어가 동시에 실행되므로 병렬 처리 효율이 극대화
- 명령어가 독립적이면 CPU 자원이 낭비되지 않음
- CPU 내부의 복잡한 스케줄링 로직이 필요하지 않아서 하드웨어 부담이 감소됨
- 명령어 워드가 길어져 코드가 커질 수 있음
- 명령어 간 의존성 문제가 발생하면 병렬 실행 불가능해질 수 있음
