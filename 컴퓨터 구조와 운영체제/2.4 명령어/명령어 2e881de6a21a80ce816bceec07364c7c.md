# 명령어

- 컴퓨터에 일을 시키려면 컴퓨터가 이해할 수 있는 말로 명령을 내려야 함
- 컴퓨터가 특정 동작을 수행하는 데 사용하는 가장 작은 단위
- 컴퓨터가 작업을 수행하게 하는 최소 단위 지시문

### 기계어와 어셈블리어

- 사람은 프로그래밍 언어를 사용해 코드를 작성하고 프로그램을 만듦
- **고급 언어**
    - C, 자바, 파이썬
    - 사람이 일상에서 사용하는 언어와 비슷한 문법 구조라서 이해하기 쉬움
    - 컴퓨터는 이해 불가
    - 컴퓨터는 오직 0과 1로 이루어진 기계어만 이해 가능
- **기계어**
    - 순수하게 이진 코드로 구성
    - CPU 아키텍쳐에 따라 다름
    - 인텔 CPU와 ARM CPU는 서로 다른 기계어 사용
    - 컴퓨터가 이해하고 실행할 수 있지만 0과 1로 이루어져서 사람이 이해하고 작성하기 어려움
    - 명령어를 사람이 이해하기 쉽게 기호나 단어로 표현한 **어셈블리어** 등장
- **어셈블리어**
    - 어셈블리어 사용 시 프로그래머가 기계어 대신, 더 읽기 쉬운 코드로 프로그래밍 가능
    - CPU 아키텍처에 특화된 언어
    - 하드 웨어를 더 세밀하게 제어
    - CPU 아키텍처에 최적화된 프로그램 작성
    - **어셈블러**라는 특수 프로그램을 통해 기계어로 변환되어 실행
- 기계어와 어셈블리어는 컴퓨터 하드웨어와 직접 상호작용하며 프로그래밍 가능 → **저급 언어**

### 컴파일 방식과 인터프리터 방식

- 소스 코드를 기계어로 변환하는 방법
- **컴파일 방식**
    - **컴파일러**라는 프로그램을 사용해 고급 언어로 작성한 소스 코드를 한 번에 기계어로 변환해 실행
    - C, C++ 등에서 이 방식 사용
    - 변환한 코드를 한 번에 실행하므로 실행 속도가 빠르며, 모든 코드를 컴파일하기 때문에 오류 미리 발견 가능
    - 컴파일 과정이 오래걸리며, 코드가 변경되면 전제를 다시 컴파일
    - 특정 운영체제나 아키텍처에 따라 컴파일한 파일이 다를 수 있음
- **인터프리터 방식**
    - **인터프리터**라는 프로그램을 사용해 소스 코드를 한 줄씩 기계어로 변환해 실행
    - 파이썬과 같은 언어가 이 방식 사용
    - 코드 수정과 디버깅이 쉽고, 실시간으로 테스트와 피드백 가능 → 개발 속도 빠름
    - 실행 시 마다 코드를 한 줄씩 해석하므로 실행 속도가 느리고 메모리 효율 저하
    - 코드를 실행해야 오류를 발견할 수 있어 디버깅이 어려움
    - 성능이 중요한 프로그램에는 부적합

### 명령어 구조

- **연산 코드**
    - 수행할 동작의 종류
    - 산술 연산, 데이터 저장, 입출력 등 다양한 작업을 지시하는 역할
- **오퍼랜드**
    - 연산의 대상이 되는 데이터나 데이터가 저장된 주소를 지정
    - 명령에 따라 수와 종류가 다름
    - 두 수를 덧셈 연산할 때 더하는 두 수가 오퍼랜드
- 명령어 구조는 연산코드와 오퍼랜드를 어떻게 조합할지, 주소 지정 방식을 무엇으로 할지 정의
- CPU가 명령어를 해석하고 실행하는 데 중요한 역할
- 명령어 구조를 이해하면 컴퓨터에서 데이터를 어떻게 처리하는지 알 수 있음

![image.png](image%202.png)

- **명령어 종류**: 산술 연산, 논리 연산, 비트 연산, 데이터 전송, 프로그램 제어, 입출력
    
    
    | **구분** | **연산 코드** | **오퍼랜드** |
    | --- | --- | --- |
    | A + B | ADD | A, B |
    | (A + B) * C | ADD, MUL | A, B, C |
- **주소 지정 방식**
    - 오퍼랜드에는 데이터를 직접 넣기보다 데이터가 저장된 주소를 지정하는 경우가 많음
    - 주소를 지정할 때는 정해진 주소 지정 방식을 따름
    - 데이터가 저장된 주소에 어떻게 접근해 데이터를 참조할지 결정하는 방법
    - 주소 지정 방식에 따라 데이터를 어떻게 가져올지, 어디에 저장할지 결정
    - **즉시 주소 지정**
        - 오퍼랜드에 실제 데이터 값을 직접 지정하는 방식
        - 명령어에 데이터가 포함
        - 상수 값을 레지스터에 로드할 때 주로 사용
        - 메모리에 접근할 필요가 없어서 빠르게 실행
        - 데이터 크기가 명령어에 포함되므로 큰 데이터에서는 사용하기 어려움
    - **레지스터 주소 지정**
        - 오퍼랜드에 레지스터를 지정해 레지스터에 저장된 데이터를 사용하는 방식
        - 레지스터 간 데이터 이동이나 연산 등 CPU 내부 작업에서 주로 사용
        - CPU 내부에 있는 레지스터에 접근하므로 속도가 매우 빠르며, 명령어가 간결하고 효율적
        - 레지스터 수가 제한적이어서 많은 데이터 처리하기 어려움
    - **직접 주소 지정**
        - 오퍼랜드에 메모리 주소를 명시해 해당 주소에서 데이터를 가져오거나 해당 주소로 데이터를 저장하는 방식
        - 변수나 상수 값이 메모리에 저장되어 있는 경우 이 데이터를 레지스터로 이동하거나 연산할 때 사용
        - 명령어가 직관적이며, 특정된 주소의 데이터에 쉽게 접근 가능
        - 메모리에 접근해야 하므로 레지스터에 접근할 때보다 느림
    - **레지스터 간접 주소 지정**
        - 오퍼랜드에 레지스터 주소를 명시하고 해당 레지스터에는 데이터가 저장된 메모리 주소를 저장하는 방식
        - 레지스터에 저장된 주소에서 실제 데이터를 가져오거나 해당 주소에 데이터를 저장
        - 포인터 연산, 동적 메모리 접근 등에 사용
        - 배열이나 포인터를 활용하는 연산에서 유용
        - 메모리에 접근해야하므로 레지스터 접근보다 느리고, 코드 복잡
    - **인덱스 주소 지정**
        - 오퍼랜드에 기본 주소와 더할 인덱스용 레지스터 주소를 지정하는 방식
        - 기본 주소에 지정된 레지스터에 저장된 값을 더해 메모리 주소를 계산
        - 계산된 메모리 주소에서 데이터를 가져오거나 해당 주소에 데이터를 저장
        - 주로 배열이나 테이블의 특정 요소에 접근할 때 사용
        - 주소를 계산해야 하므로 레지스터 주소 지정보다 느림
